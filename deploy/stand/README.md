# Тестовый стенд «Консилиума»

Стенд поднимает на одной машине всё, что нужно для тестирования:

- **веб-клиент** — открывается в браузере на компьютере и телефоне;
- **чаты случаев** с песочницей РИС/ЛИС: карточка случая, заявки ИГХ с этапами, уведомления;
- **аудио- и видеозвонки** в любом чате, демонстрация экрана;
- **API интеграции** для команды РИС/ЛИС ([docs/10-integration-api.md](../../docs/10-integration-api.md));
- **встраивание в РИС** — демо-страница `/sandbox/ris`: рабочий список с бейджами, вьюер и панель чата через SDK;
- **встраивание в ЛИС** — демо-страница `/sandbox/lis`: форма случая с плавающим чатом и «В чат» у стекла;
- **консилиум** — «Онкоконсилиум» на сегодня из трёх случаев ЛИС и РИС: повестка, роли, стенограмма по случаям, проверка и принятие протокола.

Внутри — те же компоненты, что в архитектуре: Caddy (HTTPS), Synapse и PostgreSQL, LiveKit, сервис контекста, песочница РИС/ЛИС.

> **Только вымышленные данные.** Стенд не аттестован для персональных данных и медицинской тайны: никаких реальных пациентов, ФИО, снимков и заключений.

## 1. Что нужно

| | |
|---|---|
| Машина | Linux x86-64: 2 vCPU, 4 ГБ ОЗУ, 20 ГБ диска; с ИИ-«Секретарём» — 4–6 vCPU, 16 ГБ ОЗУ, 30 ГБ диска (Ubuntu 22.04/24.04, Debian 12, Astra Linux или РЕД ОС) |
| ПО | Docker Engine 24+ с Compose 2.24+ |
| Имя | DNS-запись, например `chat-test.example.ru` → адрес машины |
| Входящие порты | 80/tcp и 443/tcp+udp — веб и HTTPS; 7881/tcp, 7882/udp, 3478/udp — медиа звонков |
| Исходящий доступ при сборке | Docker Hub и registry.npmjs.org. Если сеть подменяет сертификаты (корпоративный прокси), укажите корневой сертификат: `BUILD_CA_FILE=/путь/к/ca.crt` в `.env` |

## 2. Запуск

```bash
git clone <репозиторий> konsilium && cd konsilium/deploy/stand
./stand.sh init chat-test.example.ru admin@example.ru   # секреты и конфигурация
./stand.sh up                                           # сборка и запуск (первый раз — 5–10 минут)
./stand.sh users                                        # демо-пользователи и пароль
```

Откройте `https://chat-test.example.ru/c/lis/Г26-04512` и войдите как `smirnova` с паролем из `./stand.sh users`.

**Сертификат.** По умолчанию Caddy сам получает сертификат Let's Encrypt — для этого имя должно быть видно из интернета, а порты 80 и 443 открыты.

**Закрытая сеть или нет публичного DNS.** Используйте собственный сертификат Caddy:

```bash
TLS_MODE=internal ./stand.sh init chat-test.clinic.local
./stand.sh up
./stand.sh ca > konsilium-stand-ca.crt   # установить в доверенные корневые на устройствах тестировщиков
```

Без доверенного сертификата браузер не даст доступ к камере и микрофону.

**ИИ-«Секретарь» (по желанию).** Стенограмма звонка и черновик протокола консилиума — на процессоре стенда, без GPU и внешних сервисов. Нужно дополнительно 4 vCPU, 12 ГБ ОЗУ и 10 ГБ диска (итого машина 4–6 vCPU, 16 ГБ). При первом запуске скачивается модель (~1,1 ГБ) и образ распознавания речи (~7 ГБ).

```bash
AI=cpu ./stand.sh init chat-test.example.ru   # повторный init сохраняет секреты
./stand.sh up
```

Вместо LLM на стенде можно указать OpenAI-совместимый ИИ-шлюз организации: `AI=cpu LLM_URL=https://ai-gw.clinic.local/v1 LLM_MODEL=<модель> ./stand.sh init …`.

**Адрес для звонков.** LiveKit сам узнаёт внешний адрес машины. Если машина за NAT или адресов несколько, укажите адрес, по которому до неё достучатся тестировщики: `NODE_IP=203.0.113.10 ./stand.sh init …`, затем `./stand.sh up`.

## 3. Пользователи

`./stand.sh users` создаёт демо-пользователей с общим паролем:

| Логин | Роль | Что проверить |
|---|---|---|
| `smirnova` | Патоморфолог | Чат случая ЛИС `Г26-04512`, заявки, звонки |
| `ershova` | Лаборант ИГХ | Участник по роли, получает заявки |
| `kolesnikov` | Лечащий врач | Участник по роли |
| `gusev` | Заведующий | Не участник: вход по требованию — ЛИС разрешает через обратный вызов |
| `orlov`, `safonova`, `melnikova` | Рентгенолог, рентгенолаборант, дежурный врач | Чат случая РИС `A26-118734` |
| `belova` | — | Доступ к случаю РИС по списку из события (уровень 1) |
| `outsider` | — | Нет доступа ни к одному случаю |

Войти можно двумя способами: **«Войти через учётную запись организации»** — единый вход через Keycloak стенда (страница входа организации, затем возврат в «Консилиум»; во фрейме РИС — во всплывающем окне) — или по логину и паролю на странице «Консилиума». Логин и пароль одни и те же.

Личная учётная запись для тестировщика: `./stand.sh add-user ivanov "Иванов И. И."` (пароль покажет команда; пользователь заводится и в Keycloak). Такой пользователь видит личные чаты, но не случаи песочницы: в них участвуют только демо-пользователи.

**Synapse с воркерами.** `WORKERS=on ./stand.sh init …`, затем `./stand.sh up` — та же схема, что в окружении разработчика ([infra/README.md](../../infra/README.md#synapse-с-воркерами)): 2 воркера синхронизации, 2 воркера записи событий, Valkey; Caddy направляет синхронизацию на воркеры. Нужно ещё около 1 ГБ ОЗУ; для нагрузочных проверок — от 4 vCPU. По умолчанию выключено.

**Единый вход (Keycloak).** Включён по умолчанию (`SSO=off ./stand.sh init …` — без него). Keycloak работает за тем же доменом: `https://<домен>/auth`, консоль администратора — `/auth/admin` (логин `admin`, пароль — `KC_ADMIN_PASSWORD` в `.env`). База — `keycloak` в PostgreSQL стенда. Для пилота его заменяет Keycloak организации: в настройке Synapse меняются адреса и секрет клиента.

## 4. Что тестировать

| Сценарий | Как |
|---|---|
| Чат случая из ЛИС | Ссылка `/c/lis/Г26-04512` — так её откроет кнопка «Чат случая» в ЛИС. Проверьте карточку случая: вместо ФИО маска |
| Заявка ИГХ | В чате случая «+ Заявка в ЛИС» → блок, маркеры → «Отправить в ЛИС». Песочница принимает заявку и каждые 4 с продвигает этапы: окраска, сканирование, готово |
| Доступ по требованию | Войдите как `gusev` и откройте ту же ссылку; `outsider` получит отказ |
| Чат случая РИС | Ссылка `/c/ris/A26-118734`; для `belova` доступ по списку, для `gusev` — отказ |
| Звонок | Кнопки трубки и камеры в шапке чата. Второй участник видит «Идёт звонок · Присоединиться». Проверьте микрофон, камеру, демонстрацию экрана, «Свернуть», выход; в ленте — «Звонок завершён» с длительностью |
| Критическая находка из чата | Войдите как `smirnova` (патоморфолог) в `/c/lis/Г26-04512` → «! Критическая находка» → текст, адресат «лечащий врач», срок. У `kolesnikov` — «!» в списке, красная полоса над лентой и обратный отсчёт; «Подтверждаю получение» видят оба. Без подтверждения через 10 мин — «звонок на пост» (передаётся в песочницу ЛИС), через 15 мин в чат подключается `gusev` (заведующий) и тоже может подтвердить |
| Критическая находка из РИС | Команда в разделе 5: находка дежурному врачу (`melnikova`) в `/c/ris/A26-118734`; итог — в отчёте `GET /integration/v1/critical-findings` |
| Телефон | Тот же адрес в мобильном браузере: список и чат по очереди, звонок на весь экран |
| Уведомление из ЛИС | Команда в разделе 5 — в чате появится сообщение с кнопкой |
| ИИ-«Секретарь» (`AI=cpu`) | В звонке чата случая — кнопка со значком документа «Включить стенограмму». У всех участников индикатор «Стенограмма (ИИ)», в чате уведомление. Поговорите, нажмите «Остановить» (или завершите звонок): в чат придут стенограмма по говорящим и черновик протокола. Номера в квадратных скобках раскрывают фрагменты стенограммы; «Принять в протокол» видят все участники |
| Архив | Стенд с `ARCHIVE_AFTER_DAYS=0 ./stand.sh init …` (по умолчанию закрытый случай уходит в архив через 14 дней). Откройте `/c/team/T-1` (случай из раздела 5), напишите сообщение, затем отправьте тот же снимок с `"version":2,"status":"closed"`: в течение минуты чат уходит в архив и пропадает из списка. Папка «Архив» → случай → история целиком, чат только для чтения; «Убрать из списка». Снимок с `"version":3,"status":"open"` возвращает чат из архива |
| Встраивание в ЛИС | `https://<стенд>/sandbox/lis`, кнопка чата внизу справа, вход во фрейме как `smirnova`. «В чат» у отсканированного стекла отправляет препарат карточкой с миниатюрой; «Открыть во вьюере» в чате подсвечивает стекло в ЛИС. Сверните окно — сообщение от `kolesnikov` даст бейдж на кнопке, а при открытии — разделитель «Непрочитанные сообщения»; пока он набирает текст — «печатает…» |
| Консилиум | Войдите как `belova` (председатель) и `petrov` (секретарь), в папке «Каналы» — «Онкоконсилиум · <сегодня>»: повестка из трёх случаев с докладчиками, «Состав» с ролями. Председатель начинает звонок и включает стенограмму, «Следующий случай» — прямо в звонке; остальные видят текущий случай. После «Остановить» — черновик на каждый обсуждённый случай. Без `AI=cpu` стенограмму даёт демо-агент песочницы: девять реплик сценария (по три на случай) делят время сессии поровну — переключайте случаи примерно через равные промежутки. «Проверить и принять» → экран протокола: ссылки-время показывают фрагмент стенограммы, «Принять в протокол МИС» — после отметок «Проверено» во всех разделах; ответ «МИС» — «ожидает подписей». Копия протокола — в чате случая у `kolesnikov` (`/c/lis/Г26-04512`). Ещё один консилиум — команда в разделе 5 |
| Встраивание в РИС | `https://<стенд>/sandbox/ris`, вход во фрейме как `orlov`. «В чат исследования» отправляет ключевой снимок; «Открыть во вьюере» в чате открывает тот же кадр; сообщение `safonova` в другом исследовании даёт бейдж в рабочем списке |

## 5. Для команды РИС/ЛИС

`./stand.sh tokens` показывает адрес API интеграции и токены подключений. Подключение `team` заведено для вашей системы (уровень 1: только события).

```bash
# Снимок случая из вашей системы: чат появится, когда его откроют
curl -s https://chat-test.example.ru/integration/v1/events \
  -H "authorization: Bearer <токен team>" -H 'content-type: application/cloudevents+json' \
  -d '{"specversion":"1.0","id":"team:T-1:v1","source":"team","type":"ru.vendor.case.upserted",
       "data":{"case_id":"T-1","version":1,"title":"Биопсия, тест","patient":{"ref":"pseudo:t1","masked":"Т*** Т. Т."},
               "participants":[{"user":{"login":"smirnova"},"role":"pathologist"}],"updated_at":"2026-10-08T10:00:00+03:00"}}'

# Уведомление в чат случая песочницы (с созданием чата, если его нет)
curl -s https://chat-test.example.ru/integration/v1/events \
  -H "authorization: Bearer <токен lis>" -H 'content-type: application/cloudevents+json' \
  -d '{"specversion":"1.0","id":"demo-1","source":"lis","type":"ru.vendor.notification.posted",
       "data":{"case_id":"Г26-04512","text":"Готовы препараты ИГХ","category":"ready","ensure_chat":true}}'

# Критическая находка из «РИС» песочницы дежурному врачу: срок 2 минуты, затем заведующий
curl -s https://chat-test.example.ru/integration/v1/events \
  -H "authorization: Bearer <токен ris>" -H 'content-type: application/cloudevents+json' \
  -d '{"specversion":"1.0","id":"demo-crit-1","source":"ris","type":"ru.vendor.critical.raised",
       "data":{"case_id":"A26-118734","finding_id":"КН-1","finding":"Двусторонняя ТЭЛА","reported_by":{"login":"orlov"},
               "recipient":{"role":"on_duty"},"ack_deadline":"PT2M",
               "escalation":[{"after":"PT2M","action":"notify","target":"head","users":[{"login":"gusev"}]}]}}'

# Ещё один консилиум «МИС» песочницы: повестка из случаев ЛИС, председатель и секретарь
curl -s https://chat-test.example.ru/integration/v1/events \
  -H "authorization: Bearer <токен lis>" -H 'content-type: application/cloudevents+json' \
  -d '{"specversion":"1.0","id":"demo-ok-2","source":"lis","type":"ru.vendor.consilium.upserted",
       "data":{"consilium_id":"OK-DEMO-2","version":1,"title":"Онкоконсилиум · повтор","scheduled_at":"2026-10-09T16:00:00+03:00",
               "form":"mixed","members":[{"user":{"login":"belova"},"role":"chair"},{"user":{"login":"petrov"},"role":"secretary"},
               {"user":{"login":"kolesnikov"},"title":"онколог"},{"user":{"login":"smirnova"},"title":"патоморфолог"}],
               "agenda":[{"case_id":"Г26-04512","presenter":{"login":"kolesnikov"}},{"case_id":"Г26-04530","presenter":{"login":"smirnova"}}],
               "updated_at":"2026-10-09T10:00:00+03:00"}}'

# Отчёт по критическим находкам подключения: кто и через сколько подтвердил, эскалации
curl -s https://chat-test.example.ru/integration/v1/critical-findings -H "authorization: Bearer <токен ris>"
```

Чат случая `T-1` откроется по ссылке `/c/team/T-1`.

**Встраивание в вашу РИС/ЛИС.** Подключите `https://chat-test.example.ru/embed/v1/embed.js` (пример — исходный код страницы `/sandbox/ris`, описание — [docs/04-embedding.md](../../docs/04-embedding.md)) и разрешите домен вашей системы: `EMBED_ORIGINS="https://ris.example.ru" ./stand.sh init chat-test.example.ru`, затем `./stand.sh up`. Чтобы включить обратные вызовы (уровень 2), добавьте адрес вашей системы в `generated/connectors.json` (поле `callbacks`, как у `lis`) и выполните `./stand.sh up`.

## 6. Обслуживание

| Команда | Что делает |
|---|---|
| `./stand.sh status` | Состояние контейнеров |
| `./stand.sh logs [сервис]` | Журналы: `web`, `synapse`, `ccs`, `host-mock`, `livekit` |
| `git pull && ./stand.sh up` | Обновить стенд до новой версии (данные сохраняются) |
| `./stand.sh down` | Остановить |
| `./stand.sh destroy` | Удалить вместе с данными (спросит подтверждение) |

Секреты — в `deploy/stand/.env`, конфигурация — в `deploy/stand/generated/`. Обе папки в git не попадают.

**Если звонок не соединяется:** проверьте, что из сети тестировщика открыты 7882/udp и 7881/tcp до машины, и что LiveKit объявляет правильный адрес (`./stand.sh logs livekit` → `nodeIP`). При неверном адресе задайте `NODE_IP` (раздел 2).

## 7. Ограничения стенда

- Сервис контекста хранит случаи, связи с чатами и заявки в PostgreSQL (база `ccs` рядом с базой Synapse) — перезапуски им не страшны. Песочница РИС/ЛИС держит свои заявки в памяти: после её перезапуска старые заявки дальше не продвигаются. При старте песочница заново отправляет снимки случаев.
- Один пароль на всех демо-пользователей. Keycloak стенда — со своими пользователями; в продукте — Keycloak организации с федерацией в AD/LDAP, вход по паролю в «Консилиум» выключается.
- Нет резервного копирования и мониторинга.
- Веб-клиент — версия PoC: нет вложений, ответов, поиска по сообщениям и push-уведомлений.
- Критические находки: уведомление адресату — в открытом веб-клиенте (упоминание, полоса, «!» в списке). Push на телефон с высоким приоритетом появится вместе с мобильными приложениями; до этого держите вкладку открытой. Стенд, развёрнутый раньше, обновите: `./stand.sh init <домен>` (секреты сохранятся) и `./stand.sh up`.
- ИИ-«Секретарь» на стенде — компактные модели на процессоре (Vosk, Qwen3 1.7B): медицинские термины распознаются неидеально, черновик проще, чем у моделей на GPU. Сессия стенограммы живёт в памяти сервиса контекста: если перезапустить его во время звонка, итоги этого звонка не придут.
