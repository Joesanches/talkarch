# Тестовый стенд «Консилиума»

Стенд поднимает на одной машине всё, что нужно для тестирования:

- **веб-клиент** — открывается в браузере на компьютере и телефоне;
- **чаты случаев** с песочницей РИС/ЛИС: карточка случая, заявки ИГХ с этапами, уведомления;
- **аудио- и видеозвонки** в любом чате, демонстрация экрана;
- **API интеграции** для команды РИС/ЛИС ([docs/10-integration-api.md](../../docs/10-integration-api.md));
- **встраивание в РИС** — демо-страница `/sandbox/ris`: рабочий список с бейджами, вьюер и панель чата через SDK.

Внутри — те же компоненты, что в архитектуре: Caddy (HTTPS), Synapse и PostgreSQL, LiveKit, сервис контекста, песочница РИС/ЛИС.

> **Только вымышленные данные.** Стенд не аттестован для персональных данных и медицинской тайны: никаких реальных пациентов, ФИО, снимков и заключений.

## 1. Что нужно

| | |
|---|---|
| Машина | Linux x86-64: 2 vCPU, 4 ГБ ОЗУ, 20 ГБ диска (Ubuntu 22.04/24.04, Debian 12, Astra Linux или РЕД ОС) |
| ПО | Docker Engine 24+ с Compose 2.24+ |
| Имя | DNS-запись, например `chat-test.example.ru` → адрес машины |
| Входящие порты | 80/tcp и 443/tcp+udp — веб и HTTPS; 7881/tcp, 7882/udp, 3478/udp — медиа звонков |
| Исходящий доступ при сборке | Docker Hub и registry.npmjs.org. Если сеть подменяет сертификаты (корпоративный прокси), укажите корневой сертификат: `BUILD_CA_FILE=/путь/к/ca.crt` в `.env` |

## 2. Запуск

```bash
git clone <репозиторий> konsilium && cd konsilium/deploy/stand
./stand.sh init chat-test.example.ru admin@example.ru   # секреты и конфигурация
./stand.sh up                                           # сборка и запуск (первый раз — 5–10 минут)
./stand.sh users                                        # демо-пользователи и пароль
```

Откройте `https://chat-test.example.ru/c/lis/Г26-04512` и войдите как `smirnova` с паролем из `./stand.sh users`.

**Сертификат.** По умолчанию Caddy сам получает сертификат Let's Encrypt — для этого имя должно быть видно из интернета, а порты 80 и 443 открыты.

**Закрытая сеть или нет публичного DNS.** Используйте собственный сертификат Caddy:

```bash
TLS_MODE=internal ./stand.sh init chat-test.clinic.local
./stand.sh up
./stand.sh ca > konsilium-stand-ca.crt   # установить в доверенные корневые на устройствах тестировщиков
```

Без доверенного сертификата браузер не даст доступ к камере и микрофону.

**Адрес для звонков.** LiveKit сам узнаёт внешний адрес машины. Если машина за NAT или адресов несколько, укажите адрес, по которому до неё достучатся тестировщики: `NODE_IP=203.0.113.10 ./stand.sh init …`, затем `./stand.sh up`.

## 3. Пользователи

`./stand.sh users` создаёт демо-пользователей с общим паролем:

| Логин | Роль | Что проверить |
|---|---|---|
| `smirnova` | Патоморфолог | Чат случая ЛИС `Г26-04512`, заявки, звонки |
| `ershova` | Лаборант ИГХ | Участник по роли, получает заявки |
| `kolesnikov` | Лечащий врач | Участник по роли |
| `gusev` | Заведующий | Не участник: вход по требованию — ЛИС разрешает через обратный вызов |
| `orlov`, `safonova`, `melnikova` | Рентгенолог, рентгенолаборант, дежурный врач | Чат случая РИС `A26-118734` |
| `belova` | — | Доступ к случаю РИС по списку из события (уровень 1) |
| `outsider` | — | Нет доступа ни к одному случаю |

Личная учётная запись для тестировщика: `./stand.sh add-user ivanov "Иванов И. И."` (пароль покажет команда). Такой пользователь видит личные чаты, но не случаи песочницы: в них участвуют только демо-пользователи.

## 4. Что тестировать

| Сценарий | Как |
|---|---|
| Чат случая из ЛИС | Ссылка `/c/lis/Г26-04512` — так её откроет кнопка «Чат случая» в ЛИС. Проверьте карточку случая: вместо ФИО маска |
| Заявка ИГХ | В чате случая «+ Заявка в ЛИС» → блок, маркеры → «Отправить в ЛИС». Песочница принимает заявку и каждые 4 с продвигает этапы: окраска, сканирование, готово |
| Доступ по требованию | Войдите как `gusev` и откройте ту же ссылку; `outsider` получит отказ |
| Чат случая РИС | Ссылка `/c/ris/A26-118734`; для `belova` доступ по списку, для `gusev` — отказ |
| Звонок | Кнопки трубки и камеры в шапке чата. Второй участник видит «Идёт звонок · Присоединиться». Проверьте микрофон, камеру, демонстрацию экрана, «Свернуть», выход; в ленте — «Звонок завершён» с длительностью |
| Телефон | Тот же адрес в мобильном браузере: список и чат по очереди, звонок на весь экран |
| Уведомление из ЛИС | Команда в разделе 5 — в чате появится сообщение с кнопкой |
| Встраивание в РИС | `https://<стенд>/sandbox/ris`, вход во фрейме как `orlov`. «В чат исследования» отправляет ключевой снимок; «Открыть во вьюере» в чате открывает тот же кадр; сообщение `safonova` в другом исследовании даёт бейдж в рабочем списке |

## 5. Для команды РИС/ЛИС

`./stand.sh tokens` показывает адрес API интеграции и токены подключений. Подключение `team` заведено для вашей системы (уровень 1: только события).

```bash
# Снимок случая из вашей системы: чат появится, когда его откроют
curl -s https://chat-test.example.ru/integration/v1/events \
  -H "authorization: Bearer <токен team>" -H 'content-type: application/cloudevents+json' \
  -d '{"specversion":"1.0","id":"team:T-1:v1","source":"team","type":"ru.vendor.case.upserted",
       "data":{"case_id":"T-1","version":1,"title":"Биопсия, тест","patient":{"ref":"pseudo:t1","masked":"Т*** Т. Т."},
               "participants":[{"user":{"login":"smirnova"},"role":"pathologist"}],"updated_at":"2026-10-08T10:00:00+03:00"}}'

# Уведомление в чат случая песочницы (с созданием чата, если его нет)
curl -s https://chat-test.example.ru/integration/v1/events \
  -H "authorization: Bearer <токен lis>" -H 'content-type: application/cloudevents+json' \
  -d '{"specversion":"1.0","id":"demo-1","source":"lis","type":"ru.vendor.notification.posted",
       "data":{"case_id":"Г26-04512","text":"Готовы препараты ИГХ","category":"ready","ensure_chat":true}}'
```

Чат случая `T-1` откроется по ссылке `/c/team/T-1`.

**Встраивание в вашу РИС/ЛИС.** Подключите `https://chat-test.example.ru/embed/v1/embed.js` (пример — исходный код страницы `/sandbox/ris`, описание — [docs/04-embedding.md](../../docs/04-embedding.md)) и разрешите домен вашей системы: `EMBED_ORIGINS="https://ris.example.ru" ./stand.sh init chat-test.example.ru`, затем `./stand.sh up`. Чтобы включить обратные вызовы (уровень 2), добавьте адрес вашей системы в `generated/connectors.json` (поле `callbacks`, как у `lis`) и выполните `./stand.sh up`.

## 6. Обслуживание

| Команда | Что делает |
|---|---|
| `./stand.sh status` | Состояние контейнеров |
| `./stand.sh logs [сервис]` | Журналы: `web`, `synapse`, `ccs`, `host-mock`, `livekit` |
| `git pull && ./stand.sh up` | Обновить стенд до новой версии (данные сохраняются) |
| `./stand.sh down` | Остановить |
| `./stand.sh destroy` | Удалить вместе с данными (спросит подтверждение) |

Секреты — в `deploy/stand/.env`, конфигурация — в `deploy/stand/generated/`. Обе папки в git не попадают.

**Если звонок не соединяется:** проверьте, что из сети тестировщика открыты 7882/udp и 7881/tcp до машины, и что LiveKit объявляет правильный адрес (`./stand.sh logs livekit` → `nodeIP`). При неверном адресе задайте `NODE_IP` (раздел 2).

## 7. Ограничения стенда

- Песочница хранит заявки и случаи в памяти: после перезапуска сервиса контекста статусы старых заявок в чат не придут. При старте песочница заново отправляет снимки случаев.
- Один пароль на всех демо-пользователей; вход — по логину и паролю. Единый вход через Keycloak — в продуктовой версии.
- Нет резервного копирования и мониторинга.
- Веб-клиент — версия PoC: нет вложений, ответов, реакций, поиска по сообщениям и push-уведомлений.
