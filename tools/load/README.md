# Нагрузочный тест PoC

Проверка целей из [docs/03-architecture.md, 9.4](../../docs/03-architecture.md#94-проверка-в-poc). Результаты и выводы — в [docs/11-load-test.md](../../docs/11-load-test.md).

## Что делает

Один прогон — сценарии по очереди на отдельном стенде (чистые Synapse и PostgreSQL рядом с окружением разработчика):

| | Сценарий | Что меряем |
|---|---|---|
| A1 | Снимки случаев `case.upserted` пакетами по 100 | Время пакета, событий в секунду |
| A2 | Создание чатов случаев с постоянной частотой (открытая модель: запросы идут по расписанию, не дожидаясь ответов) | p50/p95/p99 создания, первые и последние 10 % |
| A3 | Целевой пик — 5 чатов в секунду | Задержка и достигнутая пропускная способность |
| B | События в существующие чаты: уведомления, обновления случаев | Время пакета из 50, событий в секунду |
| C | Сотни клиентов синхронизации (long-poll `/sync` с фильтром веб-клиента) и сообщения с частотой 2, 10, 30 в секунду | Задержка отправки и доставки получателям, доля доставленных |
| D | Холодный старт: первая синхронизация пользователя с 20 и 200 комнатами (по одному и всех разом), Simplified Sliding Sync | p50/p95 |
| E | Архив: «ЛИС» закрывает случаи, сервис переводит чаты в архив; участники возвращаются по одному и разом (открыть случай → войти → история) | Чатов в архив в секунду; p50/p95 возврата и его фазы |

Сервис контекста тест запускает сам — с отдельной базой и подключением `load` (уровень 1). Пользователи — `load-u0000…`, `load-h00…` (вымышленные), случаи — `L-<прогон>-<номер>`.

## Запуск

```bash
# окружение разработчика остановить: его Synapse тоже шлёт события сервису на порт 8080
cd infra && docker compose stop synapse livekit && cd ..

docker compose -p konsilium-load -f infra/docker-compose.yml -f tools/load/docker-compose.load.yml up -d synapse
pnpm --filter @konsilium/load load      # ~25 минут; итог — tools/load/results/load-<прогон>.json

# убрать стенд вместе с данными
docker compose -p konsilium-load -f infra/docker-compose.yml -f tools/load/docker-compose.load.yml down -v
```

Параметры — переменные окружения (по умолчанию в скобках): `USERS` (300), `ROOMS_PER_USER` (20), `CREATE_RATE` (2.5), `BURST` (300), `BURST_RATE` (5), `HEAVY_USERS` (5), `HEAVY_ROOMS` (200), `INTEGRATION_EVENTS` (1000), `MSG_RATES` (`2,10,30`), `STEP_S` (60), `ARCHIVE_ROOMS` (100), `SYNC_MODE` (`classic` или `sliding`), `HS_URL` (`http://localhost:18008`).

Генератор нагрузки, сервис контекста и Synapse работают на одной машине и делят процессор — цифры получаются пессимистичными. Для решения о сайзинге повторите прогон на целевом железе с конфигурацией Synapse с воркерами ([docs/11-load-test.md](../../docs/11-load-test.md), «Что дальше»).
