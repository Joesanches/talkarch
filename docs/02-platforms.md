# Выбор платформы: Zulip и альтернативы

> Факты проверены по открытым источникам на 06.10.2026, ссылки — у каждого пункта. Пометка «(по открытым данным)» означает, что факт взят из вторичных источников и его нужно перепроверить перед закупочными или юридическими решениями.

## 1. Что требуется от платформы

1. **Чат случая как объект.** Комната с метаданными: источник (РИС/ЛИС), номер случая, Study UID, этап, срок, роли участников.
2. **Свои типы сообщений.** Ключевой снимок, ROI препарата, заявка со статусом, критическая находка с подтверждением, заключение.
3. **Права доступа на уровне случая,** синхронизированные с РИС/ЛИС.
4. **Встраивание** в веб-интерфейсы РИС/ЛИС/ТМК плюс отдельные клиенты на ПК и смартфонах с Telegram-подобным UX. Почти наверняка это свои клиенты, поэтому важны API и клиентские SDK.
5. **Межорганизационное взаимодействие** для ТМК врач–врач между МО.
6. **Звонки и видеоконсилиумы.**
7. **Лицензия.** Совместима с коммерческим распространением и, вероятно, с реестром российского ПО (ПП № 1236).
8. **Нет зависимости от вендора,** который не работает с РФ.
9. **Эксплуатация on-prem** в контуре МО или региона.

## 3. Платформы подробно

### Zulip

**Лицензия и версии**

- Сервер, веб-приложение, Flutter-приложение и десктоп — Apache-2.0 ([LICENSE](https://github.com/zulip/zulip/blob/main/LICENSE), [zulip-flutter](https://github.com/zulip/zulip-flutter)).
- Актуальная ветка — Server 12 (12.0 вышел 27.04.2026, 12.3 — 21.09.2026) ([changelog](https://zulip.readthedocs.io/en/latest/overview/changelog.html)).
- Flutter-приложение с 07.06.2025 заменило React Native ([zulip-mobile](https://github.com/zulip/zulip-mobile)).

**Модель и права**

- Каналы и темы. Права — только на уровне канала: кто пишет, кто создаёт темы, кто модерирует. Доступа на уровне темы нет: подписчик видит все темы канала ([channel permissions](https://zulip.com/help/channel-permissions)).
- Для «чата случая» это значит одно из двух: приватный канал на каждый случай или тема в канале отделения — тогда видно всем в отделении.

**Шифрование и федерация**

- Сквозного шифрования нет; с 12.0 шифруется только содержимое push-уведомлений ([security](https://zulip.com/security/)).
- Федерации нет, запрос открыт с 2015 г. ([#356](https://github.com/zulip/zulip/issues/356)).

**Push для self-hosted**

- Идёт через сервис-ретранслятор Zulip. Бесплатно — до 10 пользователей, дальше платные тарифы ([billing](https://zulip.com/help/self-hosted-billing)).
- Если пересобрать мобильное приложение со своими ключами APNs/FCM, ретранслятор не нужен ([settings](https://github.com/zulip/zulip/blob/main/zproject/default_settings.py)). Для своего клиента это естественный путь.

**Встраивание:** SDK нет, nginx по умолчанию отдаёт `X-Frame-Options: DENY` ([headers](https://github.com/zulip/zulip/blob/main/puppet/zulip/files/nginx/zulip-include-common/headers)). Для собственного клиента это неважно.

**Звонки:** только ссылкой — Jitsi (по умолчанию, можно свой), BigBlueButton, Zoom и др.; мобильное приложение звонки не начинает ([providers](https://zulip.com/help/configure-call-provider)).

**Вывод.** Отличная база для внутреннего мессенджера одной организации, простая и полностью свободная. Но клинические сущности — карточка случая, заявки, критические находки — придётся целиком держать вне платформы и кодировать в Markdown.

### Matrix

**Лицензии**

- Synapse — AGPL-3.0 с версии 1.99.0 (январь 2024), коммерческая лицензия — у Element. Последний релиз — 1.162.0 от 29.09.2026 ([README](https://github.com/element-hq/synapse), [CHANGES-2024](https://github.com/element-hq/synapse/blob/develop/docs/changelogs/CHANGES-2024.md)).
- SDK [matrix-js-sdk](https://github.com/matrix-org/matrix-js-sdk) и [matrix-rust-sdk](https://github.com/matrix-org/matrix-rust-sdk) — Apache-2.0.
- [Element Web](https://github.com/element-hq/element-web) и Element X ([Android](https://github.com/element-hq/element-x-android), [iOS](https://github.com/element-hq/element-x-ios)) — AGPL-3.0 или коммерческая. **Форкать их под проприетарный продукт нельзя**; собственный клиент пишется на SDK.
- [Tuwunel](https://github.com/matrix-construct/tuwunel) — сервер на Rust под Apache-2.0, преемник conduwuit; v1.9.3 от 25.09.2026. По README спонсируется правительством Швейцарии. Зрелость для крупных инсталляций нужно проверить в PoC.
- Dart SDK (famedly) и FluffyChat — AGPL-3.0 ([pub.dev](https://pub.dev/packages/matrix), [FluffyChat](https://github.com/krille-chan/fluffychat)). Поэтому Flutter-клиент «из коробки» не подходит.

**Что даёт протокол**

- Комнаты со state-событиями и свои типы событий. Связи между событиями: ответы, треды, реакции, правки, ссылки.
- Подтверждения прочтения; пространства (иерархии комнат); виджеты.
- [Application Services](https://element-hq.github.io/synapse/latest/application_services.html) — интеграционный сервис со своим пространством имён пользователей и комнат.
- В Synapse есть JWT-вход ([jwt](https://element-hq.github.io/synapse/latest/jwt.html)). Политики хранения сообщений: на уровне сервера — стабильные, на уровне комнаты — экспериментальные ([retention](https://element-hq.github.io/synapse/latest/message_retention_policies.html)).

**Matrix 2.0**

- Simplified Sliding Sync (быстрый старт) включён в Synapse начиная с 1.114 (сентябрь 2024). MSC4186 принят в июне 2026 ([MSC4186](https://github.com/matrix-org/matrix-spec-proposals/pull/4186)).
- OAuth 2.0 API — в спецификации v1.15.
- MatrixRTC (звонки) — ещё предложение [MSC4143](https://github.com/matrix-org/matrix-spec-proposals/pull/4143). Element Call работает поверх LiveKit ([element-call](https://github.com/element-hq/element-call)).

**Matrix Authentication Service (MAS)**

- AGPL-3.0; интеграция с Synapse стабильна с 1.136.
- Нет встроенных SAML, LDAP и JWT-входа ([migration](https://github.com/element-hq/matrix-authentication-service/blob/main/docs/setup/migration.md)). Поэтому корпоративный вход строим через Keycloak, а MAS подключаем к нему как к внешнему OIDC-провайдеру.

**Внедрения в здравоохранении и госсекторе**

- Германия: национальный стандарт TI-Messenger (gematik) построен на Matrix, есть версии для медработников (Pro) и для пациентов (ePA) ([api-ti-messenger](https://github.com/gematik/api-ti-messenger)).
- По открытым данным, на март 2026 в нём зарегистрировано 7309 учреждений.
- Также Tchap (Франция) и BwMessenger (Бундесвер).

**РФ**

- Ограничений со стороны Element или Matrix.org Foundation не найдено.
- Публичный сервер matrix.org из РФ, по сообщениям пользователей, недоступен ([issue](https://github.com/element-hq/element-web/issues/28050)). Для собственного сервера в контуре МО это не важно.

**Вывод.** Лучшее соответствие требованиям 1–6. Риски — лицензия Synapse и MAS, сложность эксплуатации Synapse и незавершённая стандартизация звонков. Все три управляемы (см. раздел 5).

### Mattermost

**Лицензирование**

- Исходники — AGPL-3.0, webapp — Apache-2.0, официальные бинарники — MIT.
- Каталог `server/enterprise` — source-available, для продакшена нужна подписка ([LICENSE](https://github.com/mattermost/mattermost/blob/master/LICENSE.txt)).
- Professional — SAML, AD/LDAP. Enterprise — групповая синхронизация AD/LDAP, compliance export, политики хранения, HA-кластер ([editions](https://docs.mattermost.com/product-overview/editions-and-offerings.html)).

**v11 (16.10.2025)** ([changelog](https://docs.mattermost.com/product-overview/mattermost-v11-changelog.html))

- Новая бесплатная редакция Entry показывает и ищет только последние 10 000 сообщений на сервер.
- Team Edition ограничена 250 пользователями, из неё убраны GitLab SSO и Playbooks.

**РФ.** В 2022 г. компания прекратила работу в России (по открытым данным).

**Плюс.** Сильная система плагинов: серверные хуки на Go, webapp-плагины на React, свои типы постов ([hooks](https://github.com/mattermost/mattermost/blob/master/server/public/plugin/hooks.go)).

**Вывод.** Технически подходит, но закупить корпоративные функции нельзя, а бесплатная редакция ограничена.

### Rocket.Chat

- Код — MIT, кроме `ee/`, который требует подписки ([LICENSE](https://github.com/RocketChat/Rocket.Chat/blob/develop/LICENSE)).
- Без лицензии — до 5 приложений из маркетплейса и ни одного собственного; статусы присутствия отключаются после 200 подключений ([limits](https://github.com/RocketChat/Rocket.Chat/blob/develop/ee/packages/license/src/validation/validateDefaultLimits.ts)).
- Нужна MongoDB. E2EE — бета (по открытым данным), Matrix-федерация в 8.0 — бета.
- Есть iframe API: с 8.0 — команды `externalCommand` (по открытым данным) ([iframe](https://developer.rocket.chat/docs/iframe-integration-sending-commands)).

**Вывод.** Ограничения бесплатной версии и MongoDB перевешивают удобный iframe API.

**Вывод.** Это готовые продукты «для всех». Карточку случая, свои типы сообщений, глубокую интеграцию с РИС/ЛИС и ваш UI не сделать. Имеет смысл:

- интеграция «наружу» — уведомления в корпоративный мессенджер клиента, если он у него уже есть;
- быстрый временный вариант до готовности собственного продукта.

## 4. Рекомендация

**Matrix** (протокол и сервер) + **собственные клиенты** на matrix-js-sdk / matrix-rust-sdk (Apache-2.0) + **собственный сервис клинического контекста** (Application Service).

**Почему не Zulip, хотя он проще:**

- карточки, заявки и критические находки не являются сущностями платформы — все клинические функции пришлось бы держать во внешней БД и «склеивать» с сообщениями;
- права только на канал;
- нет федерации для ТМК между МО;
- нет звонков;
- нет клиентского SDK для быстрого Telegram-подобного клиента с офлайн-кэшем.

**Когда всё же выбрать Zulip (план Б):**

- PoC показал, что эксплуатация Matrix для типовой МО слишком тяжела;
- межорганизационное взаимодействие не нужно на горизонте 2–3 лет;
- юристы запретили Synapse, а Tuwunel не прошёл нагрузочный тест.

Архитектура (сервис контекста, свои клиенты, SDK встраивания) при этом сохраняется; меняется только адаптер к серверу.

## 5. Как снимаем риски Matrix

| Риск | Мера |
|---|---|
| Synapse и MAS — AGPL; реестр ПО | 1) Не модифицируем и не линкуем, общаемся по HTTP API. 2) Поставляем как отдельный компонент с исходниками upstream. 3) Альтернатива — Tuwunel (Apache-2.0). 4) Юр. заключение в PoC |
| Эксплуатация Synapse | Helm/Ansible, воркеры, мониторинг (Prometheus/Grafana), регламенты обновления; для малых МО — Tuwunel |
| MatrixRTC не стандартизован | Видеосвязь — Jitsi Meet on-prem: состояние звонка в комнате Matrix, вход по JWT от ССК. LiveKit — запасной вариант за тем же интерфейсом «провайдер звонков» ([03-architecture.md, раздел 7](03-architecture.md#7-видеосвязь-jitsi)) |
| MAS без SAML/LDAP/JWT | Keycloak как единый IdP (AD/LDAP/SAML), MAS или Synapse OIDC — к Keycloak |
| Нет коммерческой поддержки из РФ | Компетенции в своей команде; фиксированные версии; свой репозиторий образов |

## 6. Критерии выхода из PoC

1. Чат случая создаётся из события тестовой РИС/ЛИС за ≤ 2 с; участники синхронизируются по ролям.
2. Холодный старт веб-клиента со списком из 500 комнат — ≤ 1,5 с (Sliding Sync); переключение чата — ≤ 150 мс.
3. Нагрузка на целевом железе МО:
   - 2000 одновременных клиентов, 50 сообщений/с — p95 доставки ≤ 300 мс;
   - БД с 1 млн комнат случаев, пик создания 5 комнат/с — p95 создания ≤ 1 с;
   - возврат в архивную комнату с историей — ≤ 1 с.

   Сценарий — в [03-architecture.md, раздел 9](03-architecture.md#9-много-чатов-случаев-подход-и-масштаб).
4. Встраивание в тестовую РИС: SSO без повторного входа, передача контекста, отправка ключевого снимка, бейджи в рабочем списке.
5. Есть юр. заключение по лицензиям и выбран сервер (Synapse или Tuwunel).
6. Push на Android (RuStore + FCM) и iOS (APNs) без ПДн в содержимом.
7. Jitsi:
   - вход в конференцию только по JWT от ССК для участников комнаты;
   - звонок 1:1 с вызовом через push;
   - видеоконсилиум на 10 участников с демонстрацией вьюера;
   - никаких обращений к внешним STUN-серверам и Gravatar.
