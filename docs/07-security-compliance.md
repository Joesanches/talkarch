## 2. Принципы защиты в продукте

1. **Минимизация ПДн.**
   - В чате хранится псевдоним пациента и маска ФИО.
   - Полное ФИО по запросу отдаёт РИС/ЛИС, с проверкой прав и записью в журнал.
   - Превью снимков без «вшитых» демографических данных. Водяной знак с ФИО смотрящего накладывается при показе.
2. **Права из первоисточника.** Состав чата случая определяется назначениями в РИС/ЛИС. Экстренный доступ («разбить стекло») — с причиной и уведомлением.
3. **Нет ПДн вне контура.**
   - Push содержит только идентификатор события.
   - Никакой аналитики и crash-репортинга во внешние сервисы.
   - Обновления — из собственного репозитория.
   - Jitsi: свои STUN/TURN вместо внешних серверов из конфигурации по умолчанию, Gravatar выключен.
4. **Неизменяемый аудит.**
   - Пишется: вход, просмотр чата случая, раскрытие ФИО, экспорт, пересылка, удаление, подтверждения критических находок, изменение прав.
   - Выгрузка в SIEM (syslog/CEF).
5. **Политики хранения.**
   - Срок хранения переписки — по типу комнаты; есть юридическое удержание (legal hold).
   - Архив закрытых случаев доступен только на чтение.
6. **Видеосвязь.**
   - Вход в конференцию — только по JWT, который сервис контекста выдаёт участникам комнаты; анонимный вход запрещён.
   - Для внешних участников — лобби.
   - Запись выключена по умолчанию. Включается политикой с уведомлением участников; хранится в контуре со сроками хранения.

## 3. Меры по группам ФСТЭК (сокращённо)

| Группа | Меры в продукте |
|---|---|
| ИАФ (идентификация и аутентификация) | Единый вход через Keycloak (AD/LDAP); 2FA для внешнего доступа; PIN или биометрия на мобильных; ограничение сессий; удалённый выход с устройства |
| УПД (управление доступом) | Роли, права из РИС/ЛИС, «разбить стекло», запрет пересылки из чатов случаев за пределы контура, права на экспорт |
| РСБ (регистрация событий) | Журнал аудита (раздел 2), отчёты, выгрузка в SIEM |
| ЗНИ (защита носителей) | Шифрование БД и объектного хранилища; зашифрованный локальный кэш клиентов (SQLCipher или аналог); очистка кэша при выходе |
| ЗИС (защита ИС и каналов) | TLS 1.2+ везде, ГОСТ-TLS на периметре; закрытая федерация по списку; CSP и изоляция виджета; защита API (лимиты, WAF) |
| АНЗ, ОЦЛ (анализ защищённости, целостность) | SAST/DAST в CI, регулярный пентест, подписанные сборки, контроль зависимостей (SBOM) |
| ОДТ (доступность) | Отказоустойчивое развёртывание, резервное копирование, DR-план |

## 4. Сквозное шифрование: политика

| Тип комнаты | E2EE | Почему |
|---|---|---|
| Чат случая, ТМК, сервисный, канал | **Нет** (шифрование в канале и при хранении) | Нужны аудит, поиск, экспорт в протокол, интеграционный сервис и архив по срокам хранения |
| Личный чат | По политике организации (по умолчанию выкл.) | E2EE в Matrix (Olm/Megolm) — не сертифицированная по ГОСТ криптография, поэтому формально её недостаточно. Защиту обеспечивают ГОСТ-TLS и меры контура |

## 5. Мобильные устройства

- Обязательная блокировка: PIN или биометрия, автоблокировка через N минут.
- Скриншоты в чатах случаев: на Android запрещены (`FLAG_SECURE`); на iOS — размытие содержимого при сворачивании, предупреждение и запись в журнал о снимке экрана.
- Обнаружение root/jailbreak — по политике (предупреждение или запрет).
- Локальный кэш зашифрован; удалённый выход и очистка при утере устройства; поддержка MDM.
- Push без ПДн. Критические находки — с повышенным приоритетом (time-sensitive), но содержимое забирается только после разблокировки.
- **Распространение:**
  - Android — RuStore, корпоративный MDM, APK;
  - iOS — App Store. Риск удаления — в июне 2026 г. Apple удалила MAX, сославшись на санкции ([heise](https://heise.de/-11248047)). Резерв — веб-клиент / PWA.

## 6. Юридический статус переписки

| Ситуация | Статус | Что делает продукт |
|---|---|---|
| Рабочее обсуждение внутри МО (вопрос лаборанту, уточнение протокола) | Служебная переписка, не медицинский документ (уточнить у юристов) | Хранение по политике, аудит |
| Консультация врач–врач по 193н (в т.ч. между МО) | Телемедицинская консультация | Запрос → чат ТМК → заключение консультанта, подписанное УКЭП, → МИС/РЭМД. Переписка прикладывается по решению врача |
| Консилиум | Протокол консилиума | Повестка и обсуждение в чатах случаев → протокол в МИС с подписями |
| Критическая находка | Факт и время уведомления значимы для качества помощи | Журнал: отправлено, доставлено, прочитано, подтверждено, эскалация; отчёт по времени подтверждения |

Международные ориентиры для критических результатов:

- ACR Practice Parameter: своевременная, документируемая прямая коммуникация; одного заключения недостаточно ([ACR](https://gravitas.acr.org/PPTS/GetDocumentView?docId=74));
- Joint Commission NPSG.02.03.01: процедуры, ответственные, сроки и мониторинг своевременности.

## 7. Чек-лист для юристов и ИБ заказчика

1. Классификация: ГИС или ИСПДн; применим № 117 или № 21; уровень защищённости; модель угроз.
2. Класс СКЗИ для ГОСТ-TLS (периметр, федерация, мобильные клиенты) и требования региональной ЗСПД.
3. Покрывает ли ч. 8 ст. 10 149-ФЗ помощь по ОМС (а не только госзадание); формулировка «подведомственные организации» в 41-ФЗ.
4. Полный текст 193н: сроки ответа, хранение, регистрация в РЭМД; считается ли обсуждение внутри МО телемедицинской консультацией.
5. Лицензии: AGPL (Synapse, MAS) и включение в реестр; применимость ПП 1937 («доверенное ПО»).
6. Сроки хранения переписки по типам комнат; порядок уничтожения; юридическое удержание.
7. Порядок работы с подрядчиками (инженеры сторонних сервисных компаний): соглашения о конфиденциальности, доступ без ПДн.
